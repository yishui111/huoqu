## 4. 测试中发现并解决的问题（重点）

| 问题 | 现象 | 根因 | 解决 |
|------|------|------|------|
| 默认端口冲突 | 7860 被占 | 本机已有 pyVideoTrans 运行在 7860（保留未动） | FunClip 改用 **8315** 端口（bat 已加 `--port 8315`） |
| 启动即报错退出 | `FileNotFoundError: theme.json` | launch.py 用相对路径读主题，必须从项目**根目录**启动 | 启动 bat 改为根目录执行 `python funclip\launch.py` |
| gradio 启动后自杀 | `localhost is not accessible ... check your proxy settings` | Windows 系统代理（Clash 127.0.0.1:7897）拦截了 gradio 的本机自检请求 | 启动 bat 注入 `NO_PROXY=127.0.0.1,localhost` |
| 页面渲染 500 | `TypeError: argument of type 'bool' is not iterable` | gradio 4.44 已知 bug：pydantic v2 生成的布尔 JSON Schema 子模式无法解析 | 给 venv 内 `gradio_client/utils.py` 打两处兼容补丁（bool schema → Any/None） |
| 大模型选片偶发解析失败 | `extract_timestamps` 返回空 | 小模型输出格式不稳定：漏方括号 / 用 `-->` / 用 MM:SS | **增强上游解析器**：逐行解析，兼容 `[HH:MM:SS,mmm]`、`HH:MM:SS,mmm`、`MM:SS`、`-->`/`—`/`~`/`至` 等连接符、点号毫秒；同时把默认 Prompt 的格式要求写死。修复后批量 **2/2 成功** |
| edge-tts 偶发 NoAudioReceived | 测试素材合成中断 | 微软 TTS 接口限流 | 制作脚本加重试与间隔 |

> 说明：对 `trans_utils.py` 的解析增强和 `launch.py` 的默认模型/提示词修改属于本地改进，其余两处 gradio 补丁位于本项目 `.venv` 内，不影响系统其他 Python 环境。

## 5. 本机适配改造（相对上游）

1. **大模型全本地化**：WebUI 的 LLM 模型下拉框新增并默认选中 `litellm/ollama/qwen2.5:3b`；启动脚本设置 `LITELLM_API_BASE=http://127.0.0.1:11434`，选片不再需要任何云 API Key。
2. **模型缓存内聚**：`MODELSCOPE_CACHE` 指向项目内 `model_cache/`，不污染用户目录。
3. **双击体验**：`启动FunClip.bat`（自动拉起 Ollama → 起服务 → 开浏览器）与 `关闭FunClip.bat`（按端口精准杀进程，不误伤其他 Python 程序）。
4. **批量入口**：`批量切片.py` 一键批量"识别→选片→裁剪+字幕"，日志写入 `测试运行日志.txt`。
