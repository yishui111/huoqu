# FunClip · 接口文档

> **项目用途**：长视频 → 本地语音识别 → 按文本/说话人裁剪 → 烧字幕出爆款切片。
> 两个入口：Gradio 工作台（`启动FunClip.bat`，8315，给人用）和本 REST 服务（`启动接口服务.bat`，8335，给程序用）。

- 启动：双击 `启动接口服务.bat`（或 `.venv\Scripts\python.exe api_server.py`）
- 地址：`http://127.0.0.1:8335`，自带交互文档 `http://127.0.0.1:8335/docs`
- 模型：首次调用识别接口时懒加载 FunASR paraformer-zh（缓存在 `model_cache/`，约 30 秒加载）；进程内常驻，之后秒级响应
- 说明：本 REST 服务走**无 LLM 的确定性裁剪**（给文本就裁）；AI 挑高光需 Ollama，请用 Gradio 页面

## 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查（模型是否已加载、缓存的任务数） |
| POST | `/api/recog` | 上传视频/音频 → 异步识别（全文 + SRT） |
| GET | `/api/transcript/{id}` | 取识别结果（全文文本、SRT 字幕） |
| POST | `/api/clip` | 按文本片段裁剪（可烧字幕）→ 异步出片 |
| GET | `/api/job/{id}` | 任务进度 `queued → running → done/error` |
| GET | `/api/result/{id}` | 下载成片 mp4 |

## 调用示例（识别 → 裁剪 → 下载，三步）

```bash
# ① 上传并识别
curl -X POST http://127.0.0.1:8335/api/recog -F "file=@长视频.mp4"
# → {"ok":true,"data":{"task_id":"7ebc99cf3647"}}

# ② 轮询识别进度；完成后取全文（text）与 SRT（srt）
curl http://127.0.0.1:8335/api/job/7ebc99cf3647
curl http://127.0.0.1:8335/api/transcript/7ebc99cf3647

# ③ 从全文里挑一段话裁剪（text 必须是识别原文的连续片段），烧字幕
curl -X POST http://127.0.0.1:8335/api/clip \
  -H "Content-Type: application/json" \
  -d '{"recog_id":"7ebc99cf3647","text":"香蕉其实是浆果","add_sub":true,"font_size":32}'

# ④ 轮询 done 后下载成片
curl -o 切片.mp4 http://127.0.0.1:8335/api/result/<clip任务id>
```

## 参数说明

**POST /api/clip**（JSON body）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| recog_id | str | 必填 | 之前 `/api/recog` 返回的任务 id |
| text | str | 必填 | 要裁剪的原文连续片段（识别是无标点文本，取词要含在原文里） |
| font_size | int | 32 | 字幕字号 |
| add_sub | bool | true | 是否烧录字幕到画面 |

## 实测记录（2026-09-28，RTX 4080）

- 90 秒测试视频识别：模型加载 ~35s + 识别 ~13s
- 「香蕉其实是浆果」裁剪 + 烧字幕：8 秒内出片（73KB mp4）
- 识别任务的结果缓存在内存（`_states`），服务重启后需重新识别
