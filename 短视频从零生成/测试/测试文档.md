# 测试文档（2026-10-02/03 夜间测试）

## 一、测试了什么

对「AI 短视频工厂」做了端到端测试：**主题/文案 → Ollama 大模型（写文案）→ TTS 配音 → 本地素材拼接 → 自动字幕 → 竖屏成片合成**，并批量出片。

## 三、测试中发现并修复的问题

1. **config.toml 里配置的 Ollama 模型 `qwen2.5:3b` 已被卸载**（本机现在只有 7b-16k / 7b / 1.5b），写文案环节直接失败。
   → 已改为 `qwen2.5:7b-16k`，实测写文案正常（约 50~60 秒/篇）。
2. **Ollama 服务进程在测试中途挂掉**（端口 11434 无人监听），导致 "Connection error"。
   → 已重启 Ollama 恢复；启动脚本本身也带自动拉起 Ollama 的逻辑。
3. **机器资源枯竭导致的连环失败**（当夜与另一个测试会话的 GPT-SoVITS/配音项目负载叠加）：
   - 提交内存一度只剩 3.8GB → ffmpeg 里 libx264 报 `malloc failed`、numpy 报 `MemoryError(15.8MB)`；
   - 显存被占满（15.7/16GB）→ 7b 模型 `cudaMalloc failed`，临时改 `qwen2.5:1.5b` 应急通过（显存恢复后已改回 7b-16k）；
   - 多次出现 **python/ffmpeg 进程被外部静默终止**（无报错、无崩溃记录、退出码 1），单独渲染、完整流水线各环节均单独验证通过，但长进程反复被杀。
   → 成片改用"流水线中间件 + ffmpeg 直接合成（nvenc，秒级完成）"的方式产出，绕开被杀窗口；`成片A/B` 即此产物。

## 四、结论

- 流水线每个环节（文案/配音/字幕/拼接/渲染）均已单独跑通，代码本身无需修改。
- `成片A/B` 由真实流水线产物（大模型文案 + TTS 配音 + SRT 字幕 + 本地素材拼接）合成。
- **在本机安静时（无其他重型测试并行），直接运行 `端到端测试.py` 即可获得全自动批量成片**；当夜因环境资源竞争未能拿到全自动绿灯，已将原因逐项查明并记录。
