## 2. 部署过程记录

1. 走镜像 `gh-proxy.com` 克隆仓库（直连 GitHub 被墙）。
2. `py -3.12 -m venv .venv` + 清华 PyPI 镜像安装依赖，全部安装成功，`import moviepy, streamlit, edge_tts, faster_whisper, litellm` 通过。
3. 复制 `config.example.toml → config.toml`，改了 4 处：
   - `llm_provider = "ollama"`、`ollama_model_name = "qwen2.5:3b"`（本地大模型，零 Key）
   - `video_codec = "h264_nvenc"`（RTX 4080 硬件编码）
   - `log_level = "INFO"`
4. **顺手修复了一个系统级故障**：本机 `C:\Users\dapanji\.ollama` 是一个指向 `D:\aistore\.ollama` 的符号链接，但目标目录不存在，导致 Ollama 一直起不来（连带「解说模型」工作台的大模型回退也坏了）。已创建 `D:\aistore\.ollama` 修复，Ollama 恢复正常。
5. 拉取了两个本地模型：`qwen3.5:4b`（3.4GB）、`qwen2.5:3b`（约 2GB）。

## 4. 测试中发现并解决的问题

| 问题 | 现象 | 解决 |
|------|------|------|
| Ollama 起不来 | `models path not accessible` 反复退出 | 符号链接目标 `D:\aistore\.ollama` 不存在 → 已创建，服务正常 |
| 首选模型输出无标点 | qwen3.5:4b 生成的文案没有任何标点 → 字幕整段 40 秒糊成一块 | 换 `qwen2.5:3b`，文案带标点、字幕正常分句，速度还快一倍 |
| 中文参数乱码风险 | Windows 控制台 GBK 编码 | bat 用 GBK 编码写入；批量测试脚本用 UTF-8 Python 封装 |
| `timeout /t` 冲突 | Git Bash 环境下误命中 GNU timeout | 关闭 bat 改用 `ping -n 3` 延时，任何环境都稳 |
